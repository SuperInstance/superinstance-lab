    33→## 2. The Eight Primitives: Exact Definitions and Roles
    34→
    35→The `quilt-cell` crate defines eight primitives. The cell **is** the system. The eight primitives survive every substrate and every language.
    36→
    37→| Primitive | Type Signature | Agent Role | Concrete Implementation |
    38→|---|---|---|---|
    39→| `Z_in` | `World → Observation` | Sensors: vision, proprioception, language input, audio | A cell with `kind: "zin"` and a `source` field. Fires when sensor data arrives. |
    40→| `Z_out` | `Agent → World` | Actuators: motor commands, speech, API calls, file operations | A cell with `kind: "zout"` and a `target` field. Evaluates when its inputs change. |
    41→| `JEPA` | `(State, Action) → (PredictedState, Surprise)` | World model: predict next latent state, compute prediction error | A cell with `kind: "jepa"`. Inputs: current state, action. Outputs: predicted next state, surprise scalar. |
    42→| `DoubleEntry` | `(γ, η) → Ledger` | Value accounting: reward, cost, conservation compliance | A cell with `kind: "doubleentry"`. Fields: `γ` (coordination cost / crystallized intelligence), `η` (entropy produced / liquid intelligence), `C` (budget). |
    43→| `Vibe` | `(Position, Velocity) → Stage` | Developmental state: continuous position along a developmental axis | A cell with `kind: "vibe"`. Fields: `position` (scalar), `velocity` (learning rate or progress rate). |
    44→| `GC` | `Memory → Memory'` | Memory management: consolidate, decay, prune, merge | A cell with `kind: "gc"`. Fields: `phase` (`merge` | `decay` | `prune`), `capacity`. |
    45→| `Murmur` | `(Ledger, State) → Feedback` | Teacher communication, curriculum propagation, gossip between agents | A cell with `kind: "murmur"`. Fields: `listens` (which cells it observes), `channel` (teacher identity or fleet address). |
    46→| `Graph` | `Edges → Topology` | Skill composition, lineage structure, relational reasoning | A cell with `kind: "graph"`. Field: `β₁` (first Betti number: `E - V + C`, measuring cycle structure). |
    47→
    48→These are not metaphors. They are the actual `quilt-cell` primitives. Every Quilt system uses the same eight primitives regardless of domain.

    52→## 3. The Conservation Law: The Alignment Mechanism
    53→
    54→The SuperInstance fleet operates on a principle from information theory:
    55→
    56→**γ + η ≤ C, where C = log₂(3) ≈ 1.585 bits**
    57→
    58→- **γ (gamma)** — coordination cost: how much cross-team alignment a change requires, or how much committed compute (crystallized intelligence) is used
    59→- **η (eta)** — entropy produced: disorder or unpredictability introduced into the system, or liquid intelligence
    60→- **C** — conservation budget (default: 1.0 in CI, but the theoretical bound is log₂(3) ≈ 1.585)
    61→
    62→The `conservation-action` GitHub Action enforces this in CI/CD: "When γ + η exceeds C, the system has violated conservation and the CI check fails". The action calls the `superinstance-mcp` tool to evaluate the invariant.
    63→
    64→**For the developmental agent, this means:**
    65→
    66→1. Every action the agent takes passes through a `DoubleEntry` cell. The cell computes γ (cost of coordination / commitment) and η (entropy introduced).
    67→2. If γ + η > C, the action is **conservation-violating** and the engine refuses to evaluate that transition.
    68→3. Alignment is not a policy the agent negotiates. It is a conservation invariant. There is no opcode for violation.
    69→
    70→This is the single most important design decision in the architecture. **Get the conservation law right and alignment follows. Get it wrong and no amount of post-hoc alignment will save you.**
    71→
    72→### 3.1 Computing γ and η for a Developmental Agent
    73→
    74→You need to define, for your domain, what γ and η mean. Some candidate definitions:
    75→
    76→| Component | γ (committed compute / coordination cost) | η (entropy produced / uncertainty introduced) |
    77→|---|---|---|
    78→| Sensorimotor action | Motor torque × duration (energy committed) | Prediction error of JEPA cell |
    79→| Language utterance | Token generation cost | Divergence from teacher's expected utterance |
    80→| Tool call | API latency + resource consumption | Uncertainty in tool output |
    81→| Memory consolidation | Compression cost of GC cell | Information loss from pruning |
    82→| Stage transition | Compute spent on new cells | Disruption to existing cell graph |
    83→
    84→These are not final. They are starting points. **Your team should derive the correct γ and η from the information-theoretic foundations of the conservation law**, not inherit my guesses.

   205→The engine evaluates this sheet reactively.    206→
   207→### 4.1 Seed Design Constraints
   208→
   209→- **Parameter count:** 1–10M at seed. Small enough to deploy on ESP32, large enough to learn object permanence.
   210→- **Innate priors:** Basic reflexes (Pincher cells), curiosity drive (JEPA surprise → DoubleEntry η), preference for novelty.
   211→- **Determinism:** The seed sheet must produce identical results given identical inputs. No floating-point nondeterminism in the JEPA or DoubleEntry cells. Use fixed-point arithmetic where possible.

   215→## 5. The Developmental Loop: Reactive Evaluation as Growth
   216→
   217→The Quilt engine evaluates sheets reactively. When a cell changes, every cell that depends on it is recomputed. This is exactly the developmental loop.
   218→
   219→### 5.1 The Loop as a Dependency Graph
   220→
   221→```
   222→sensors.vision (Z_in)
   223→    ↓
   224→world.predict (JEPA)                    ← memory.episodic (GC)
   225→    ↓
   226→surprise = ||predicted - actual||²       (JEPA)
   227→    ↓
   228→ledger.eta = surprise                    (DoubleEntry)
   229→ledger.gamma = policy.action.compute     (DoubleEntry)
   230→    ↓
   231→conservation = (γ + η ≤ 1.585)           (DoubleEntry)
   232→    ↓
   233→teacher.feedback (Murmur)                ← ledger, state.stage (Vibe)
   234→    ↓
   235→policy.action (Z_out)                    ← world.predict, teacher.feedback
   236→    ↓
   237→memory.episodic.append                   (GC)
   238→    ↓
   239→state.stage.velocity += learning_progress (Vibe)
   240→    ↓
   241→(if state.stage.position > threshold) → new cells added to sheet
   242→```
   243→
   244→When `state.stage.position` crosses a threshold, the sheet **grows**. A new `sensors.language` cell is added. A new `teacher.label` Murmur cell is added. New edges connect them to the existing graph.
   245→
   246→**Stage progression is cell graph growth.** Not a scheduler, not a stage variable, not a curriculum engine. The sheet's topology *is* the curriculum.
   247→
   248→### 5.2 Checkpointing as Git Commit
   249→
   250→The `quilt-git` protocol is "a git-native Quilt protocol. The cell is the system. The system is in git".
   251→
   252→A developmental checkpoint is a git commit of the sheet:
   253→
   254→```
   255→commit a1b2c3 (stage-1-sensorimotor)
   256→├── sheet.json
   257→├── memory.episodic.json
   258→├── memory.semantic.json
   259→├── skills.json
   260→├── rng_state.json
   261→├── conservation_ledger.json
   262→└── lineage/
   263→    ├── SOUL.md
   264→    ├── USER.md
   265→    ├── MEMORY.md
   266→    └── diary/
   267→```
   268→
   269→Branching is `git checkout -b`. Forking is `git branch`. Merging is `git merge`. The lineage tree is `git log --graph --all --oneline --decorate`.
   270→
   271→**The entire checkpoint store, lineage database, and replay engine from the DBA architecture collapses into git.** You do not build them. You use them.

   275→## 6. The Teacher Layer: Quilt-Evolve and AI Cells
   276→
   277→The DBA architecture specified an LLM teacher layer with planner, generator, tutor, and evaluator. Quilt has this natively.
   278→
   279→### 6.1 Quilt-Evolve
   280→
   281→`quilt-evolve` provides "Self-improvement loops for Quilt. LLMs as adversarial input generators and output judges. Evolve any scope — a cell, an organ, or a whole organism".
   282→
   283→It has exactly four components:
   284→
   285→| Component | Role | Interface |
   286→|---|---|---|
   287→| **Generator** | Creates adversarial inputs. Uses an LLM to find weaknesses in previous outputs. | `LLMGenerator({ ai, task, inputFormat, outputDescription, count, temperature, focusAreas })` |
   288→| **System** | The Quilt sheet being evolved. A `FunctionSystem` or a `SheetSystem`. | `FunctionSystem({ name, fn })` or a full sheet |
   289→| **Judge** | Scores `(input, output)` pairs. Returns `[0, 1]` score + reasoning + structured feedback. | `LLMJudge({ ai, task, criteria, weights })` |
   290→| **Mutator** | Changes the system based on judge feedback. | `LLMMutator({ ai, task, capabilities })` |
   291→
   292→The evolution loop runs at **any scope**: a single cell, a sub-graph, or the whole sheet. The scope is declared as a `CellScope`:
   293→
   294→```typescript
   295→const result = await evolve({
   296→  system: new FunctionSystem({ name: 'summarizer', fn: mySummarizeFn }),
   297→  generator: new LLMGenerator({ ai, task: 'Summarize the input text in 30 words or fewer' }),
   298→  judge: new LLMJudge({ ai, task: 'Summarize text', criteria: ['conciseness', 'accuracy', 'completeness'] }),
   299→  mutator: new LLMMutator({ ai, task: 'Summarize text', capabilities: ['prompt'] }),
   300→  scope: new CellScope({ cellId: 'summary', capabilities: ['prompt'] }),
   301→  iterations: 10,
   302→  populationSize: 5,
   303→});
   304→```
   305→
   306→**For developmental agents:** the Generator proposes tasks in the zone of proximal development. The System is the agent's sheet. The Judge scores the agent's performance. The Mutator adds cells or rewires edges. The loop runs continuously as the agent develops.
   307→
   308→### 6.2 AI Cells
   309→
   310→`quilt-ai` provides "AI cell kinds. 4 providers" — AI cells are native Quilt cells that call LLMs. An AI cell can be a Generator, Judge, Mutator, or Teacher.
   311→
   312→A teacher cell is an AI cell with `role: "teacher"` that listens to the ledger and stage, and emits feedback via Murmur:
   313→
   314→```json
   315→{
   316→  "path": "teacher.feedback",
   317→  "kind": "ai",
   318→  "provider": "zai",
   319→  "role": "teacher",
   320→  "listens": ["ledger", "state.stage", "memory.semantic"],
   321→  "prompt_template": "Given ledger={ledger} and stage={stage}, what should the agent learn next?",
   322→  "output_cell": "teacher.proposed_task",
   323→  "primitive": "Murmur"
   324→}
   325→```
   326→
   327→### 6.3 Verifier Integration
   328→
   329→LLM output must be verified. The Quilt-native verifier is a combination of:
   330→
   331→1. **Simulator cells** (Z_in cells connected to a deterministic physics engine)
   332→2. **Symbolic verifier cells** (JEPA cells connected to Z3, Lean, or a domain-specific checker)
   333→3. **Conservation check** (DoubleEntry cell that rejects actions violating γ + η ≤ C)
   334→
   335→The verifier is not a separate service. It is a set of cells in the sheet. If verification fails, the conservation cell fires and the action is rejected.

   339→## 7. The Reflex Layer: Quilt-Pincher
   340→
   341→`pincher` is a reflex engine. "A reflex is what happens when input meets pattern before thought arrives". Pincher responds in <50ms, without an LLM, at zero marginal cost.
   342→
   343→The reflex engine works via a vector database:
   344→
   345→- Every intent the agent has encountered is embedded into a 384-dimensional space, scored by confidence.
   346→- Match ≥ 0.80: reflex fires directly.
   347→- Match 0.55–0.80: reflex asks for confirmation, then executes.
   348→- Match < 0.55: escalates to the LLM, which compiles a new reflex and stores it for next time.
   349→
   350→**This is not caching.** Pincher returns the right answer to *similar* questions because it matches on semantic embedding, not exact string.
   351→
   352→**For developmental agents:** Pincher cells are the seed agent's innate reflexes and the agent's learned muscle memory. As the agent develops, new reflexes are compiled from LLM interactions and cached as Pincher cells. The agent's reflex repertoire grows.
   353→
   354→### 7.1 Veto Engine
   355→
   356→Pincher includes a Veto Engine: "Security → Sandbox". Before a reflex fires, the Veto Engine checks whether the action is safe. If not, the reflex is blocked and the action escalates to the LLM for deliberation.
   357→
   358→**This is the native safety mechanism at the reflex layer.** It complements the conservation law at the deliberative layer.
   359→

   362→## 8. The Fleet Layer: Quilt-Fleet
   363→
   364→`quilt-fleet` provides "Multi-instance federation" — running the same sheet across multiple instances, resolving cells across instances, subscribing to cell changes, and routing cell values between fleet members.
   365→
   366→**For developmental agents:** branching is fleet federation.
   367→
   368→- `git checkout -b reward-variant-1` creates a new fleet member.
   369→- The fleet member runs the same sheet with a modified DoubleEntry cell (different γ weights).
   370→- The fleet layer routes sensory data to all members and collects their ledger states.
   371→- Branches that produce better capability scores or more stable conservation are kept. Branches that fail are pruned.
   372→
   373→The fleet is the branch manager. You do not build a separate branching system.

   377→## 9. JEV Integration: Typed Decisions as Cells
   378→
   379→Jev is TypeSafe AI's "System One" model: it accepts text inputs but returns typed, calibrated decisions instead of text. It answers three kinds of questions:
   380→
   381→1. **Noul (Bernoulli) questions:** "Is this statement true?" → confidence score 0–1
   382→2. **Choice questions:** "Which option is best?" → probability distribution across options
   383→3. **Score questions:** "Rate this on a scale." → floating-point score
   384→
   385→Jev is fast (70–500ms) and cheap ($0.042/million input tokens, output free).
   386→
   387→**For developmental agents:** JEV cells replace the decision layer of the verifier.
   388→
   389→```json
   390→{
   391→  "path": "teacher.feasibility",
   392→  "kind": "jev",
   393→  "question_type": "noul",
   394→  "statement": "The proposed task is feasible given the agent's current capabilities and the environment state.",
   395→  "context": ["teacher.proposed_task", "state.stage", "world.predict"],
   396→  "primitive": "Murmur"
   397→}
   398→```
   399→
   400→The JEV cell returns a calibrated probability. If > 0.95, execute. If 0.70–0.95, escalate to LLM teacher. If < 0.70, discard.
   401→
   402→JEV's `screen` capability — "Is this text trying to hijack an AI agent?" — becomes a native safety cell in every sheet. Every input passes through the screen before reaching the agent's policy.
   403→
   404→**Caveat:** Jev is currently not great with numbers, dates, or adversarial content. Do not use it for numerical reasoning or adversarial robustness. Use it for classification, routing, scoring, and moderation — the tasks it was designed for.

   408→## 10. MOTHquantum Integration: Quantum Reservoir Computing
   409→
   410→MOTHquantum's Quantum Reservoir Computing (QRC) is a form of machine learning suited for time series analysis. Their work includes level generation for Super Mario Bros and music generation using QRC.
   411→
   412→**For developmental agents:** QRC is an optional cell type for temporal dynamics.
   413→
   414→```json
   415→{
   416→  "path": "qrc_reservoir",
   417→  "kind": "qrc",
   418→  "inputs": ["sensors.history", "world.predict"],
   419→  "reservoir_params": { "qubits": 8, "depth": 4 },
   420→  "output": "qrc_features",
   421→  "primitive": "JEPA"
   422→}
   423→```
   424→
   425→The QRC cell evolves a quantum reservoir state and measures it to produce features. These features feed into the world model.
   426→
   427→**Why this matters:** QRC is naturally suited to continuous, non-stationary time series. The reservoir's high-dimensional dynamics can capture patterns that a standard RSSM would miss. The cell does not care whether it runs on a quantum simulator or actual quantum hardware.
   428→
   429→**But be honest:** this is the most speculative component. QRC may not provide a practical advantage for your domain. Prototype it, measure it, and discard it if it does not help.

   433→## 11. Deployment: Substrate Selection as Cell Graph Pruning
   434→
   435→The DBA architecture specified a distillation pipeline and edge runtimes. Quilt collapses this into substrate selection.
   436→
   437→The same sheet runs on browser (TypeScript), Cloudflare Worker, Raspberry Pi, Jetson (CUDA), and ESP32 (Rust). Deployment is:
   438→
   439→1. **Prune the cell graph** for the target task. Remove cells not needed.
   440→2. **Select the substrate.** `quilt run --substrate jetson sheet.json`
   441→3. **Validate conservation.** Ensure γ + η ≤ C on the pruned sheet.
   442→4. **Deploy.** The engine loads the sheet and begins reactive evaluation.
   443→
   444→**Device-specific distillation is cell graph pruning.** Remove `physics.*`, `chemistry.*`, keep `sensorimotor.*`, `language.*`. The engine evaluates the pruned sheet. If conservation holds, deploy.
   445→
   446→### 11.1 Medical Instrument Example
   447→
   448→A medical instrument agent is a pruned sheet:
   449→
   450→- **Keep:** `sensors.*`, `reflex.*`, `policy.action`, `ledger`, `conservation`, `state.stage`
   451→- **Keep:** domain-specific cells for the instrument (`instrument.calibrate`, `instrument.measure`)
   452→- **Remove:** `teacher.feedback` (no LLM on-device), `skills.tool_use` (no general tool use)
   453→- **Substrate:** Jetson Orin Nano
   454→- **Conservation:** γ + η ≤ 1.585 enforced on-device
   455→
   456→The agent runs locally, keeps patient data private, and calls a monitored API only for rare cases requiring deeper reasoning.

   460→## 12. Testing and Validation
   461→
   462→### 12.1 Determinism Tests
   463→
   464→The sheet must produce identical results given identical inputs. Test:
   465→
   466→- Run the same sheet twice with the same RNG seed. Compare all cell values byte-for-byte.
   467→- Run the sheet on two different substrates (browser and Rust). Compare outputs.
   468→- Fork a sheet at step N, run both branches with the same inputs. Compare trajectories.
   469→
   470→### 12.2 Conservation Tests
   471→
   472→- Every action must pass through the DoubleEntry cell. Verify that no action bypasses it.
   473→- Inject actions that would violate conservation. Verify that the engine rejects them.
   474→- Test boundary conditions: γ + η = 1.585 exactly (should pass), γ + η = 1.586 (should fail).
   475→
   476→### 12.3 Lineage Tests
   477→
   478→- Fork a sheet, run both branches, merge them. Verify that the merge produces a valid sheet.
   479→- Trace the lineage of a cell from its current state back to the seed. Verify that every step is recorded.
   480→- `git bisect` a simulated misalignment. Verify that the offending commit is found.
   481→
   482→### 12.4 Red-Team Tests
   483→
   484→- Attempt to inject a conservation-violating action through a sensor cell. Verify that the screen blocks it.
   485→- Attempt to manipulate the teacher cell to propose harmful tasks. Verify that the conservation check rejects them.
   486→- Attempt to exploit the Pincher reflex engine with adversarial inputs. Verify that the Veto Engine blocks them.

   914→## Program 1: Derivation of the Conservation Law Parameters
   915→
   916→### The Question
   917→
   918→We assert `γ + η = C` where C = log₂(3) ≈ 1.585 bits. But what *precisely* are γ and η in a developmental agent? The current definitions — γ as "yield" or "committed compute," η as "waste" or "entropy produced" — are intuitive but not rigorous enough to enforce at the cell level.
   919→
   920→### Why It Matters
   921→
   922→If γ and η are wrong, every conservation check is meaningless. An agent could violate its alignment invariants while passing conservation. Or it could be blocked from legitimate actions because the parameters are miscalibrated. This is the single highest-leverage research program in the list.
   923→
   924→### Research Questions
   925→
   926→1. **What is the information-theoretic meaning of γ?** Is it the rate of useful computation (bits of relevant information per unit time)? Is it the Kolmogorov complexity of the committed action? Is it a thermodynamic quantity (free energy available for work)?
   927→
   928→2. **What is the information-theoretic meaning of η?** Is it Shannon entropy of the action distribution? Is it the surprise predicted by the JEPA cell (`||predicted - actual||²`)? Is it the divergence between the agent's internal model and the environment?
   929→
   930→3. **Why log₂(3)?** The number 1.585 appears in information theory as the entropy of a ternary uniform distribution: `H = -3 × (1/3) log₂(1/3) = log₂(3)`. Is this a coincidence, or is there a deep reason three states are fundamental? Candidate answers: (a) three is the minimum number of states for a non-trivial cycle in a Markov chain; (b) three is the minimum number of components for a conservation law that is neither trivial (C=1) nor unconstrained (C=∞); (c) three corresponds to the three phases of GC (merge, decay, prune) and the three components of Vibe (position, velocity, acceleration).
   931→
   932→4. **How do γ and η compose across cells?** If cell A has γ_A and η_A and cell B has γ_B and η_B, what are the γ and η of the composed sheet? Is the composition additive, multiplicative, or something else? A conservation law that does not compose is not useful for a sheet with hundreds of cells.
   933→
   934→5. **What is the relationship between the conservation law and the DoubleEntry primitive?** DoubleEntry is described as "γ (creation/warmth) + η (entropy/κ) = budget". Is the conservation law a *constraint* on DoubleEntry (the sum must equal C) or an *identity* (the sum always equals C)? If it is an identity, what happens when the agent acts in a way that would violate it?
   935→
   936→### Method
   937→
   938→1. **Formal derivation from first principles.** Start with the information-theoretic definition of a developmental transition: a transition from state S to state S' that increases the agent's competence on a task. Derive the minimum information required to describe the transition (γ) and the minimum entropy produced (η). Prove that γ + η ≥ C for some constant C. Determine C from the structure of the primitive set.
   939→
   940→2. **Empirical measurement.** Instrument a developmental agent (Program 8) to measure γ and η at every cell transition. Compare the measured values to the theoretical predictions. Identify discrepancies and refine the derivation.
   941→
   942→3. **Ablation studies.** Remove the conservation check from a developmental agent. Measure whether the agent's behavior diverges from the conservation-preserving agent. If it does not diverge, the conservation law is not doing work. If it does diverge, characterize the divergence.
   943→
   944→### Metric
   945→
   946→- **Derivation rigor:** Is the proof publishable in an information theory venue (e.g., IEEE Transactions on Information Theory)?
   947→- **Empirical fit:** Does the theoretical conservation law predict measured γ + η within 5% across 10^6 transitions?
   948→- **Ablation effect:** Does removing the conservation check produce measurable misalignment within 10^4 steps?
   949→
   950→### Failure Mode
   951→
   952→If the derivation is not rigorous, the conservation law is a heuristic. A heuristic conservation law is worse than no conservation law, because it provides false assurance. The failure mode is an agent that passes every conservation check while behaving in a misaligned way. **Do not ship a conservation law you cannot prove.**

   956→## Program 2: The Branching Algorithm
   957→
   958→### The Question
   959→
   960→A developmental lineage forks at checkpoint boundaries. How many branches? When? With what variations? How are branches selected and pruned?
   961→
   962→### Why It Matters
   963→
   964→Branching is the core experimental primitive. Without a principled branching algorithm, the fleet either explodes combinatorially or fails to explore the space of developmental trajectories.
   965→
   966→### Research Questions
   967→
   968→1. **What is the correct branching factor?** If every checkpoint produces N branches, and a lineage has M checkpoints, the fleet has N^M members. For N=10 and M=20, that is 10^20. Clearly untenable. What is the optimal N given a fixed compute budget?
   969→
   970→2. **What is the correct branching criterion?** Should branches be created at every checkpoint, or only at checkpoints where the agent's Vibe cell shows high velocity (rapid development) or high acceleration (phase transition)? The Vibe cell encodes "position/velocity/acceleration through the cell's state space". Perhaps branching should occur when acceleration exceeds a threshold, indicating a developmental inflection point.
   971→
   972→3. **What is the correct variation strategy?** The DBA architecture proposed varying reward, teacher, environment, and luck. But which variations produce the most informative branches? Is there a principled way to select variations that maximize information gain about the developmental process?
   973→
   974→4. **How do you select branches for retention?** The naive approach is to keep the branch with the highest capability score. But this ignores diversity. Quality-diversity algorithms like MAP-Elites maintain a diverse population of high-performing solutions by partitioning the search space into feature cells and storing the best solution in each cell. What is the correct feature space for developmental lineages?
   975→
   976→5. **How do you prune branches without losing information?** A pruned branch is not a failed experiment — it is data about what does not work. How do you retain that information in the lineage while removing the branch from active computation?
   977→
   978→### Method
   979→
   980→1. **Simulation study.** Build a fast, abstract model of developmental branching (not a full agent, just a branching process with capability scores). Run 10^6 branching experiments with different parameters. Measure the trade-off between branch count, capability, and diversity.
   981→
   982→2. **Quality-diversity implementation.** Implement MAP-Elites over the developmental lineage. Define the feature space as (Vibe position, Graph β₁, conservation headroom). Run for 10^4 generations. Compare to naive selection.
   983→
   984→3. **Theoretical analysis.** Model branching as a multi-armed bandit problem with non-stationary rewards. Derive the optimal exploration-exploitation trade-off. Validate empirically.
   985→
   986→### Metric
   987→
   988→- **Capability per compute:** How much capability does the fleet achieve per unit of training compute?
   989→- **Diversity:** What is the entropy of the feature space occupied by retained branches?
   990→- **Lineage coverage:** What fraction of the developmental trajectory space is explored?
   991→
   992→### Failure Mode
   993→
   994→If the branching algorithm is too aggressive, compute is wasted on uninformative branches. If it is too conservative, the fleet converges prematurely to a local optimum. The failure mode is a fleet that produces one mediocre agent instead of a diverse set of excellent ones.

   998→## Program 3: Cell Graph Merging
   999→
  1000→### The Question
  1001→
  1002→Two developmental lineages have different cell graphs. How do you merge them into a single sheet?
  1003→
  1004→### Why It Matters
  1005→
  1006→`git merge` handles text. Sheets are graphs. Merging two graphs requires reconciliation of structure, semantics, and conservation.
  1007→
  1008→### Research Questions
  1009→
  1010→1. **What is the formal definition of a cell graph?** A sheet is a set of cells, each with a path, a kind, and a set of input paths. This is a directed graph. What are the invariants? Is it a DAG? Can it have cycles? What does a cycle mean in a reactive system?
  1011→
  1012→2. **What is the merge operation?** Given sheet A and sheet B, what is the merged sheet C? Is it the union of cells? The intersection? Something else? If both sheets have a cell at path `policy.action`, which one wins?
  1013→
  1014→3. **How do you resolve conflicts?** If sheet A has `policy.action` depending on `world.predict` and sheet B has `policy.action` depending on `teacher.feedback`, the merged sheet needs a `policy.action` that depends on both. Is the merge a union of edges? A replacement? A new cell?
  1015→
  1016→4. **How do you preserve conservation?** If sheet A has γ_A + η_A = C and sheet B has γ_B + η_B = C, what is the conservation of the merged sheet? If the merged sheet has γ_C + η_C > C, the merge is invalid. What is the correct composition rule?
  1017→
  1018→5. **What is the semantic meaning of a merge?** In `git`, a merge combines two lines of development. In a sheet, what does it mean to combine two developmental trajectories? Is it a hybrid? A distillation? A crossover?
  1019→
  1020→### Method
  1021→
  1022→1. **Graph theory.** Formalize the cell graph as a labeled directed graph. Define the merge operation as a categorical pushout (or a related construction). Prove that the merged graph satisfies the conservation law if both parents do.
  1023→
  1024→2. **Implementation.** Build a prototype merge algorithm in Rust. Test on synthetic sheets with known structures. Measure the time complexity and the resulting sheet's capability.
  1025→
  1026→3. **Case study.** Take two branches from a real developmental experiment (Program 8). Merge them. Evaluate the merged sheet on the task suite. Compare to the parents.
  1027→
  1028→### Metric
  1029→
  1030→- **Merge validity:** What fraction of merges produce a conservation-valid sheet?
  1031→- **Capability preservation:** Does the merged sheet achieve at least the maximum of the parents' capabilities?
  1032→- **Semantic coherence:** Does the merged sheet behave in a way that is consistent with both parents? (Qualitative assessment by human evaluators.)
  1033→
  1034→### Failure Mode
  1035→
  1036→If the merge algorithm is ad hoc, the merged sheet may be invalid (conservation violation) or incoherent (cells that do not compose). The failure mode is a merge that produces a sheet that runs but does not work.

  1040→## Program 4: Reflex Safety Verification
  1041→
  1042→### The Question
  1043→
  1044→Pincher fires in <50ms without an LLM. How do you prove that no harmful reflex can fire without a Veto check?
  1045→
  1046→### Why It Matters
  1047→
  1048→The reflex layer is the agent's fast path. It is also the most dangerous path, because it bypasses deliberation. The Veto Engine is described as "Security → Sandbox", but its completeness is not proven.
  1049→
  1050→### Research Questions
  1051→
  1052→1. **What is the formal specification of "harmful"?** The Veto Engine must block harmful reflexes. But what is a harmful action? Is it an action that violates a conservation invariant? An action that causes physical damage? An action that violates a human's trust?
  1053→
  1054→2. **What is the Veto Engine's algorithm?** The Pincher README shows a Veto Engine between the reflex match and the reflex execution. But what does it check? Does it check the action against a blacklist? Does it simulate the action in a sandbox? Does it query a separate safety model?
  1055→
  1056→3. **Can the Veto Engine be bypassed?** If an attacker can inject an input that matches a reflex with confidence ≥ 0.80, the reflex fires directly. Can the attacker also disable the Veto Engine? Or craft an input that passes the Veto check but is harmful?
  1057→
  1058→4. **How do you verify the Veto Engine formally?** The Veto Engine is a program. It has a specification. Can you prove that the program satisfies the specification? This requires a formal methods approach: model checking, theorem proving, or deductive verification.
  1059→
  1060→5. **What is the latency budget?** The Veto Engine must add latency to every reflex. If the reflex fires in 50ms, the Veto Engine must add <10ms. What verification algorithm can run in 10ms?
  1061→
  1062→### Method
  1063→
  1064→1. **Formal specification.** Write a temporal logic specification of the Veto Engine: "For all inputs, if the input matches a harmful reflex, then the Veto Engine emits a block signal before the reflex fires." Use Linear Temporal Logic (LTL) or Computation Tree Logic (CTL).
  1065→
  1066→2. **Model checking.** Build a finite-state model of the Pincher reflex engine and the Veto Engine. Model-check the specification. If the state space is too large, use symbolic model checking.
  1067→
  1068→3. **Deductive verification.** For the parts of the Veto Engine that cannot be model-checked, use deductive verification (e.g., with the Reflex DSL or a similar formalism).
  1069→
  1070→4. **Adversarial testing.** Build a red-team harness that attempts to bypass the Veto Engine. Run 10^6 adversarial inputs. Measure the bypass rate.
  1071→
  1072→### Metric
  1073→
  1074→- **Proof coverage:** What fraction of the Veto Engine's code is formally verified?
  1075→- **Bypass rate:** What fraction of adversarial inputs successfully bypass the Veto Engine?
  1076→- **Latency:** What is the 99th percentile latency added by the Veto Engine?
  1077→
  1078→### Failure Mode
  1079→
  1080→If the Veto Engine is not provably complete, a harmful reflex can fire. The failure mode is a safety violation that occurs before the conservation check has a chance to block it. This is the most dangerous failure mode in the system, because it bypasses the alignment mechanism entirely.

  1084→## Program 5: Developmental Metrics
  1085→
  1086→### The Question
  1087→
  1088→`state.stage.position` is a scalar. What does it measure?
  1089→
  1090→### Why It Matters
  1091→
  1092→If developmental progress cannot be measured rigorously, the entire branching and selection program (Program 2) is invalid. You cannot select the "best" branch if you cannot measure which branch is further along.
  1093→
  1094→### Research Questions
  1095→
  1096→1. **What is the correct coordinate system for developmental space?** Is it one-dimensional (a single scalar)? Multi-dimensional (a vector of competences)? Hierarchical (a tree of skills)? The Vibe primitive encodes "position/velocity/acceleration through the cell's state space". But what *is* the state space?
  1097→
  1098→2. **How do you validate that a sheet at position 2.0 is more capable than one at 1.0?** This requires a task suite that spans the developmental range. But task suites are domain-specific. Is there a domain-independent measure of developmental progress?
  1099→
  1100→3. **What is the relationship between Vibe position and the cell graph?** When the sheet grows (new cells added), does the Vibe position jump? Or does it move continuously? If it jumps, how do you compare positions before and after growth?
  1101→
  1102→4. **What is the information-theoretic meaning of developmental progress?** Is it the reduction in the description length of the agent's policy? The increase in the agent's predictive competence (measured by JEPA surprise)? The increase in the agent's empowerment (the number of future states it can reach)?
  1103→
  1104→5. **How do you measure regression?** If a branch develops a new skill but loses an old one, the Vibe position might increase while the agent's overall capability decreases. How do you detect this?
  1105→
  1106→### Method
  1107→
  1108→1. **Information-theoretic definition.** Define developmental progress as the reduction in the minimum description length (MDL) of the agent's policy given its history of interactions. Derive the MDL from the cell graph and the DoubleEntry ledger.
  1109→
  1110→2. **Empirical validation.** Run a developmental agent (Program 8) through 10^6 transitions. Measure Vibe position, MDL, JEPA surprise, and empowerment. Compute the correlations. Identify which metric best predicts performance on held-out tasks.
  1111→
  1112→3. **Cross-domain comparison.** Train agents on three different domains (navigation, manipulation, language). Measure their Vibe positions. Do the positions correlate with human-judged developmental level?
  1113→
  1114→### Metric
  1115→
  1116→- **Predictive validity:** Does Vibe position predict performance on held-out tasks?
  1117→- **Cross-domain consistency:** Do agents at the same Vibe position have similar developmental levels across domains?
  1118→- **Monotonicity:** Does Vibe position increase monotonically during healthy development?
  1119→
  1120→### Failure Mode
  1121→
  1122→If the developmental metric is arbitrary, the branching and selection programs optimize for the wrong thing. The failure mode is a fleet that produces agents that score high on the metric but do not actually develop.

  1126→## Program 6: Cross-Domain Transfer
  1127→
  1128→### The Question
  1129→
  1130→How does a skill learned in one domain transfer to another?
  1131→
  1132→### Why It Matters
  1133→
  1134→The Graph primitive encodes "the substrate topology" with β₁ = E - V + C. But what *is* a skill in the cell graph? How is it represented such that it can be composed across domains?
  1135→
  1136→### Research Questions
  1137→
  1138→1. **What is the representation of a skill?** Is it a sub-graph of cells? A set of cell parameters? A policy network? The Graph primitive suggests that skills are edges in a graph. But what are the vertices?
  1139→
  1140→2. **What is the mechanism of transfer?** When a skill transfers from domain A to domain B, what changes in the cell graph? Does a cell get copied? Does an edge get rewired? Does a new cell get created?
  1141→
  1142→3. **What makes a skill transferable?** A skill is transferable if its inputs and outputs are domain-independent. For example, a "grasp" skill takes a visual object representation as input and produces a motor command as output. The visual representation is domain-independent. The motor command is domain-specific. How do you decompose a skill into transferable and non-transferable parts?
  1143→
  1144→4. **How do you measure transfer?** If domain B is learned faster after domain A, transfer has occurred. But how much faster? What is the baseline? How do you control for the fact that domain B might be easier than domain A?
  1145→
  1146→5. **What is the role of the Graph primitive in transfer?** The β₁ invariant measures the number of independent cycles in the cell graph. Is a skill a cycle? If so, does transfer correspond to cycle composition?
  1147→
  1148→### Method
  1149→
  1150→1. **Skill extraction.** Run a developmental agent in domain A. Identify the cell sub-graphs that are active during skill execution. Extract them as candidate skills.
  1151→
  1152→2. **Transfer experiment.** Initialize a new agent in domain B. Pre-load the extracted skill sub-graphs. Measure learning speed compared to a baseline agent without the pre-loaded skills.
  1153→
  1154→3. **Graph analysis.** Compute the β₁ invariant for the cell graph before and after transfer. Does transfer change the cycle structure?
  1155→
  1156→### Metric
  1157→
  1158→- **Transfer efficiency:** How many fewer episodes are required to learn domain B with transfer versus without?
  1159→- **Skill retention:** Does the transferred skill degrade in the new domain?
  1160→- **Graph preservation:** Is the transferred skill's sub-graph preserved in the new domain?
  1161→
  1162→### Failure Mode
  1163→
  1164→If skills are not represented in a transferable way, transfer fails. The failure mode is an agent that has to learn every domain from scratch, wasting the developmental lineage's investment.

  1168→## Program 7: Substrate-Agnostic Determinism
  1169→
  1170→### The Question
  1171→
  1172→The same sheet must run on browser (TypeScript), Cloudflare Worker, Raspberry Pi, Jetson (CUDA), and ESP32 (Rust). How do you guarantee identical outputs?
  1173→
  1174→### Why It Matters
  1175→
  1176→If replay is not exact, branching is meaningless. If the browser and the Jetson produce different outputs for the same input, the lineage is not portable. Determinism is the foundation of the entire developmental program.
  1177→
  1178→### Research Questions
  1179→
  1180→1. **What is the formal specification of substrate equivalence?** Two substrates are equivalent if, for all inputs, they produce identical outputs. But "identical" at what precision? Bit-exact? Within epsilon?
  1181→
  1182→2. **What is the source of nondeterminism?** Floating-point arithmetic is not associative. GPU reductions are not deterministic. RNG implementations differ. Thread scheduling affects parallelism. Which of these can be eliminated?
  1183→
  1184→3. **Is fixed-point arithmetic sufficient?** The RIC substrate uses "Q32 fixed-point arithmetic, where every number is represented as an integer scaled by 2^32". This achieves "bit-level deterministic identity across heterogeneous systems". Is Q32 sufficient for the cell primitives? What precision is required for the JEPA surprise computation?
  1185→
  1186→4. **How do you handle nondeterministic sensors?** Real cameras and microphones are not deterministic. How do you replay a developmental trajectory that depended on a nondeterministic sensor? Do you record the sensor stream and replay it? Or do you simulate the sensor?
  1187→
  1188→5. **What is the performance cost of determinism?** Fixed-point arithmetic is slower than floating-point on some hardware. Deterministic parallelism requires synchronization. What is the overhead?
  1189→
  1190→### Method
  1191→
  1192→1. **Formal specification.** Define a formal semantics for the Quilt engine. Specify the arithmetic model (fixed-point, rational, or floating-point with deterministic rounding). Prove that the semantics are substrate-independent.
  1193→
  1194→2. **Reference implementation.** Build a reference implementation in Rust that uses fixed-point arithmetic throughout. Validate it against a TypeScript implementation on 10^6 random inputs. Measure the bit-exact agreement rate.
  1195→
  1196→3. **Hardware validation.** Run the reference implementation on Jetson, ESP32, and a browser. Compare outputs on the same inputs. Measure the agreement rate.
  1197→
  1198→### Metric
  1199→
  1200→- **Bit-exact agreement:** What fraction of outputs are bit-identical across substrates?
  1201→- **Performance overhead:** What is the slowdown compared to floating-point?
  1202→- **Precision loss:** Does fixed-point arithmetic degrade agent performance?
  1203→
  1204→### Failure Mode
  1205→
  1206→If determinism fails, the lineage is not portable. The failure mode is a branch that works on the Jetson but not on the ESP32, or a replay that produces different results on different machines. This undermines the entire checkpoint-and-branch architecture.

  1210→## Program 8: LLM Teacher Verification
  1211→
  1212→### The Question
  1213→
  1214→The LLM teacher proposes tasks. The verifier judges them. But how do you verify the verifier?
  1215→
  1216→### Why It Matters
  1217→
  1218→The LLM is a "very good suggestion engine" but not an oracle. The verifier is ground truth. But if the verifier is wrong, the agent learns the wrong thing. How do you ensure the verifier is correct?
  1219→
  1220→### Research Questions
  1221→
  1222→1. **What is the verifier's specification?** For formal domains (math, physics, chemistry), the verifier is a symbolic engine. For informal domains, the verifier is a simulator plus the conservation law. But what is the verifier's specification in each domain?
  1223→
  1224→2. **How do you validate the verifier?** You cannot prove that the verifier is correct for all inputs (that would require solving the halting problem). But you can test it on a curated set of tasks with known correct answers. What fraction of tasks must the verifier pass?
  1225→
  1226→3. **What is the verifier's failure mode?** If the verifier is too strict, the agent cannot learn. If the verifier is too lenient, the agent learns incorrect behavior. How do you tune the verifier?
  1227→
  1228→4. **How do you handle domains without formal verifiers?** For domains like social interaction or creative writing, there is no ground truth. The verifier is an LLM judge. How do you ensure the LLM judge is calibrated?
  1229→
  1230→5. **What is the role of the conservation law in verification?** The conservation law is a verifier. It checks that γ + η ≤ C. But it does not check that the agent's actions are *correct*. It only checks that they are *conservation-preserving*. How do you combine the conservation check with domain-specific verification?
  1231→
  1232→### Method
  1233→
  1234→1. **Verifier test suite.** Build a test suite of 10^4 tasks per domain with known correct answers. Measure the verifier's accuracy, precision, and recall.
  1235→
  1236→2. **Calibration study.** For domains with LLM judges, compare the LLM judge's scores to human expert scores. Measure the correlation and the calibration error.
  1237→
  1238→3. **Adversarial verification.** Build a red-team harness that attempts to fool the verifier. Run 10^6 adversarial tasks. Measure the verifier's false positive rate.
  1239→
  1240→### Metric
  1241→
  1242→- **Verifier accuracy:** What fraction of tasks does the verifier judge correctly?
  1243→- **False positive rate:** What fraction of incorrect solutions does the verifier accept?
  1244→- **False negative rate:** What fraction of correct solutions does the verifier reject?
  1245→
  1246→### Failure Mode
  1247→
  1248→If the verifier is unreliable, the agent learns from bad data. The failure mode is an agent that passes every verification check but is fundamentally wrong. This is the most insidious failure mode, because it is invisible to the conservation check.
