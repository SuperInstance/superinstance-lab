   480→   480→- **Change a seed** → All downstream checkpoints recalculate.

   497→   497→## 3. Architecture for SuperInstance DBA
   498→   498→
   499→   499→### 3.1 Layer 1: The Cell Runtime
   500→   500→
   501→   501→Each cell runs a **micro-agent** — a small, self-contained instance that can:
   502→   502→
   503→   503→- Load a checkpoint.
   504→   504→- Execute a growth step.
   505→   505→- Save a new checkpoint.
   506→   506→- Report capability and value scores.
   507→   507→
   508→   508→The cell runtime is the **agent runtime**. It's lightweight enough to run thousands of cells in parallel.
   509→   509→
   510→   510→```python
   511→   511→class CellRuntime:
   512→   512→    def __init__(self, checkpoint=None, formula=None):
   513→   513→        self.checkpoint = checkpoint or SeedCheckpoint()
   514→   514→        self.formula = formula
   515→   515→        self.history = []
   516→   516→    
   517→   517→    def recalculate(self, inputs):
   518→   518→        """Execute the formula, producing a new checkpoint."""
   519→   519→        op = parse_formula(self.formula)
   520→   520→        new_checkpoint = op.execute(self.checkpoint, inputs)
   521→   521→        self.history.append(new_checkpoint)
   522→   522→        return new_checkpoint
   523→   523→    
   524→   524→    def fork(self, modifications):
   525→   525→        """Create a new cell runtime with modified state."""
   526→   526→        child = copy.deepcopy(self)
   527→   527→        child.checkpoint = apply_modifications(self.checkpoint, modifications)
   528→   528→        child.parent = self
   529→   529→        return child
   530→   530→```
   531→   531→
   532→   532→### 3.2 Layer 2: The Dependency Engine
   533→   533→
   534→   534→The dependency engine tracks references between cells and schedules recalculation. This is the **lineage tracker** and **replay engine** combined.
   535→   535→
   536→   536→```python
   537→   537→class DependencyEngine:
   538→   538→    def __init__(self):
   539→   539→        self.graph = {}  # cell_id -> {precedents, dependents}
   540→   540→        self.cache = {}  # cell_id -> checkpoint
   541→   541→    
   542→   542→    def add_cell(self, cell_id, precedents):
   543→   543→        self.graph[cell_id] = {"precedents": precedents, "dependents": []}
   544→   544→        for p in precedents:
   545→   545→            self.graph[p]["dependents"].append(cell_id)
   546→   546→    
   547→   547→    def recalculate(self, cell_id):
   548→   548→        """Recalculate a cell and all dependents."""
   549→   549→        cell = self.cells[cell_id]
   550→   550→        inputs = [self.cache[p] for p in self.graph[cell_id]["precedents"]]
   551→   551→        new_checkpoint = cell.recalculate(inputs)
   552→   552→        self.cache[cell_id] = new_checkpoint
   553→   553→        for d in self.graph[cell_id]["dependents"]:
   554→   554→            self.recalculate(d)
   555→   555→    
   556→   556→    def lineage(self, cell_id):
   557→   557→        """Return the full ancestry of a cell."""
   558→   558→        return trace_precedents(self.graph, cell_id)
   559→   559→```
   560→   560→
   561→   561→### 3.3 Layer 3: The Quilt Composer
   562→   562→
   563→   563→The quilt composer stitches sheets together. A quilt is a **composition of developmental tracks**:
   564→   564→
   565→   565→```
   566→   566→Quilt "Medical Instrument Agent":
   567→   567→  ├── Sheet "Sensorimotor" (from lineage A)
   568→   568→  ├── Sheet "Language" (from lineage B)
   569→   569→  ├── Sheet "Medical Domain" (from lineage C)
   570→   570→  └── Sheet "Safety" (from lineage D)
   571→   571→```
   572→   572→
   573→   573→Each sheet is a patch. The quilt is the composed agent. The composer ensures:
   574→   574→
   575→   575→- **Interface compatibility**: The output of one sheet matches the input of another.
   576→   576→- **Version compatibility**: Sheets from different lineages can be stitched if their interfaces match.
   577→   577→- **Value coherence**: Sheets don't have conflicting value systems.
   578→   578→
   579→   579→```python
   580→   580→class QuiltComposer:
   581→   581→    def compose(self, sheets):
   582→   582→        """Stitch sheets into a quilt."""
   583→   583→        quilt = Quilt()
   584→   584→        for sheet in sheets:
   585→   585→            quilt.add_patch(sheet, interface=sheet.output_interface)
   586→   586→        quilt.validate()
   587→   587→        return quilt
   588→   588→    
   589→   589→    def stitch(self, quilt, patch, position):
   590→   590→        """Add a patch to an existing quilt."""
   591→   591→        if not quilt.can_accept(patch, position):
   592→   592→            raise IncompatiblePatch()
   593→   593→        quilt.insert(patch, position)
   594→   594→        return quilt
   595→   595→```

   871→   871→| **Z_out** | Actuators: motor commands, speech, API calls | `{ kind: "zout", path: "actuators.motor", target: "joints" }` |
   872→   872→| **JEPA** | World model: predict next state, compute surprise | `{ kind: "jepa", path: "world.predict", inputs: ["sensors", "memory"], surprise: true }` |
   873→   873→| **DoubleEntry** | Value ledger: reward, cost, conservation accounting | `{ kind: "doubleentry", path: "ledger", γ: "curiosity", η: "error", C: "budget" }` |
   874→   874→| **Vibe** | Developmental state: position, velocity, stage | `{ kind: "vibe", path: "state.stage", position: 0, velocity: "learning_rate" }` |
   875→   875→| **GC** | Memory: consolidate, decay, prune | `{ kind: "gc", path: "memory.episodic", phase: "merge|decay|prune" }` |
   876→   876→| **Murmur** | Teacher feedback, curriculum propagation, gossip | `{ kind: "murmur", path: "teacher.feedback", listens: ["ledger", "state"] }` |
   877→   877→| **Graph** | Skill composition, lineage, relational structure | `{ kind: "graph", path: "skills", β₁: "E - V + C" }` |
   878→   878→
   879→   879→This is not a metaphor. The `quilt-cell` crate already defines these eight primitives: `Z_in`, `Z_out`, `Jepa`, `DoubleEntry`, `Vibe`, `Gc`, `Murmur`, `Graph`. The cell *is* the system. The 8 primitives survive every substrate and every language.
   880→   880→
   881→   881→A seed agent is a sheet with one cell of each primitive. Development is the sheet acquiring more cells and more edges.
   882→   882→
   883→   883→---
   884→   884→
   885→   885→## 3. Development as Reactive Evaluation
   886→   886→
   887→   887→In the DBA architecture, "development" was a training loop: run episodes, collect transitions, update weights, checkpoint. In Quilt-native, development is **the engine evaluating the sheet as new sensory data arrives.**
   888→   888→
   889→   889→Here's the loop, expressed as cell dependencies:
   890→   890→
   891→   891→```
   892→   892→sensors.vision (Z_in)
   893→   893→    ↓
   894→   894→world.predict (JEPA)          ← memory.episodic (GC)
   895→   895→    ↓
   896→   896→surprise = ||predicted - actual||²   (JEPA)
   897→   897→    ↓
   898→   898→ledger.curiosity = surprise            (DoubleEntry)
   899→   899→    ↓
   900→   900→teacher.feedback (Murmur)     ← ledger, state.stage (Vibe)
   901→   901→    ↓
   902→   902→policy.action (Z_out)         ← world.predict, teacher.feedback
   903→   903→    ↓
   904→   904→memory.episodic.append          (GC)
   905→   905→    ↓
   906→   906→state.stage.velocity += learning_progress   (Vibe)
   907→   907→```
   908→   908→
   909→   909→When a sensor fires, the engine recomputes every dependent cell. That recomputation *is* the developmental step. There is no separate "training loop." The sheet is the loop.
   910→   910→
   911→   911→This is the first simplification: **you delete the training loop and the agent runtime from the DBA architecture.** They become cell dependencies.
   912→   912→
   913→   913→---
   914→   914→
   915→   915→## 4. Cell Graph Growth as Stage Progression
   916→   916→
   917→   917→How does the agent move from sensorimotor to language to domain expertise? Not by a stage variable that the scheduler increments. By **the sheet acquiring new cells and new edges.**
   918→   918→
   919→   919→Stage 0 (sensorimotor): the sheet has ~12 cells. `sensors.vision`, `world.predict`, `policy.action`, `memory.episodic`, `ledger`, `state.stage`. The edges are direct.
   920→   920→
   921→   921→Stage 1 (language): a new Z_in cell `sensors.language` appears. A new Murmur cell `teacher.label` appears. Edges connect `sensors.language` → `world.predict` and `teacher.label` → `memory.semantic`. The sheet grew.
   922→   922→
   923→   923→Stage 2 (tool use): new Z_out cells `actuators.api`, `actuators.file`. New Graph cell `skills.tool_use`. Edges connect `world.predict` → `skills.tool_use` → `actuators.api`.
   924→   924→
   925→   925→Stage 3 (domain): new cells for domain-specific concepts. New JEPA cells for domain dynamics. New DoubleEntry cells for domain rewards. New Graph cells for domain procedures.
   926→   926→
   927→   927→The **Vibe cell** tracks the stage as a continuous position, not a discrete label. `state.stage.position` moves as cells are added and competence improves. The engine's reactive evaluation propagates this position to every dependent cell.
   928→   928→
   929→   929→This is the second simplification: **you delete the curriculum scheduler and the stage transition logic.** The sheet's cell graph *is* the curriculum. Adding cells *is* advancing stages.
   930→   930→
   931→   931→---

   933→   933→## 5. Checkpointing as Git-Native Lineage
   934→   934→
   935→   935→The DBA architecture specified a checkpoint store, a lineage database, and a replay engine. Quilt has `quilt-git`: "a git-native Quilt protocol. The cell is the system. The system is in git. The protocol is below the app".
   936→   936→
   937→   937→A developmental checkpoint is a git commit of the sheet. The sheet is a JSON document. The commit includes `sheet.json`, `memory.episodic.json`, `memory.semantic.json`, `skills.json`, `rng_state.json`, and the lineage markdown. Branching is `git checkout -b`. Forking is `git branch`. Merging is `git merge`. The lineage tree is `git log --graph`.
   938→   938→
   939→   939→This is the third simplification: **you delete the checkpoint store, lineage database, and replay engine.** They become git.
   940→   940→
   941→   941→The `Live Canon` package adds 7 operations on the cell fabric: `NAVIGATE`, `CONFLUENCE`, `LINEAGE`, `GHOST`, `TICK`, `CLAIM`, `DRILL`. These are native lineage and replay operations.
   942→   942→
   943→   943→---
   944→   944→
   945→   945→## 6. Branching as Quilt-Fleet
   946→   946→
   947→   947→The DBA architecture had a "Branch Manager" that forked checkpoints and ran them in parallel. Quilt has `quilt-fleet`: "Multi-instance federation". A branch is a fleet member. The fleet runs the same sheet on different substrates with different modifications.
   948→   948→
   949→   949→The `quilt-fleet` layer handles: resolving cells across instances, subscribing to cell changes, and routing cell values between fleet members.
   950→   950→
   951→   951→This is the fourth simplification: **you delete the branch manager.** Branching is fleet federation.
   952→   952→

   954→   954→
   955→   955→## 7. Alignment as Conservation Law
   956→   956→
   957→   957→This is the deepest native move. The DBA architecture treated alignment as reward shaping plus value probes plus red-teaming. Quilt has a conservation law at its core:
   958→   958→
   959→   959→**γ + η ≤ C where C = log₂(3) ≈ 1.585**
   960→   960→
   961→   961→where γ is committed compute (crystallized intelligence) and η is entropy produced (liquid intelligence).
   962→   962→
   963→   963→The `DoubleEntry` primitive encodes this: "γ (creation/warmth) + η (entropy/κ) = budget". The `conservation-action` repo enforces this in CI: "When γ + η exceeds C, the system has violated conservation and the CI check fails". The `fleet-budget` repo enforces it at the database level as a CHECK constraint.
   964→   964→
   965→   965→**Alignment is a conservation invariant on the sheet.** A developmental agent's values are cells that participate in the DoubleEntry ledger. An action that violates a value — deception, harm, oversight violation — is an action that breaks conservation. The engine will not evaluate that transition because the DoubleEntry cell's constraint is violated.
   966→   966→
   967→   967→This is not a policy the agent negotiates. It is physics of the sheet. The conservation law is the fence. It is deterministic, auditable, and non-negotiable. There is no opcode for violation.
   968→   968→
   969→   969→This is the fifth simplification: **you delete the alignment layer, the value probe harness, and the red-team system as separate components.** They become DoubleEntry cells with conservation constraints.
   970→   970→
   971→   971→---
   972→   972→
   973→   973→## 8. The LLM Teacher as AI Cells + Quilt-Evolve
   974→   974→
   975→   975→The DBA architecture had an "LLM Teacher Layer" with planner, generator, tutor, and evaluator agents. Quilt has:
   976→   976→
   977→   977→- `quilt-ai`: "AI cell kinds. 4 providers". An AI cell is a cell that calls an LLM. It's a native cell kind.
   978→   978→- `quilt-evolve`: "Self-improvement loops for Quilt. LLMs as adversarial input generators and output judges. Evolve any scope — a cell, an organ, or a whole organism".
   979→   979→
   980→   980→`quilt-evolve` has exactly four components: **Generator** (creates adversarial inputs), **Judge** (scores outputs), **Mutator** (changes the system), and **System** (the Quilt sheet being evolved). The loop runs at any scope: a single cell, a sub-graph, or the whole sheet.
   981→   981→
   982→   982→This is the sixth simplification: **you delete the teacher layer.** The teacher is a Generator cell + a Judge cell + a Mutator cell. The student is the System. `quilt-evolve` is the developmental engine.
   983→   983→
   984→   984→The `quilt-elf` repo provides "Invisible elves. LLM-powered background workers". These are Murmur cells that run in the background, proposing tasks and feedback without blocking the sheet's reactive evaluation.
   985→   985→

   987→   987→
   988→   988→## 9. Reflexes as Quilt-Pincher
   989→   989→
   990→   990→The DBA architecture had an "Agent Core" with a policy network. Quilt has `quilt-pincher`: "Reflex engine as Quilt cells". Pincher is "a reflex engine. A reflex is what happens when input meets pattern before thought arrives". Reflexes fire in ~50ms.
   991→   991→
   992→   992→A developmental agent's reflexes are Pincher cells. They fire before the LLM teacher is consulted. They are the seed agent's innate priors. As the agent develops, new reflexes are learned and cached as Pincher cells. This is "muscle memory" — cached patterns that fire without the LLM.
   993→   993→
   994→   994→This is the seventh simplification: **you delete the policy network as a separate component.** It becomes a collection of Pincher reflex cells.

   999→   999→
  1000→  1000→The DBA architecture had a deployment layer with distillation, edge runtimes, and API gateways. Quilt already runs the same sheet on:
  1001→  1001→
  1002→  1002→- Browser (TypeScript)
  1003→  1003→- Cloudflare Worker
  1004→  1004→- Raspberry Pi
  1005→  1005→- Jetson (CUDA)

  1007→  1007→
  1008→  1008→The same sheet, the same engine, different runtimes. `quilt-jetson` provides NVIDIA Jetson runtime with CUDA. Simple quilts run on ESP32s for engine, weather, and water sensors.
  1009→  1009→
  1010→  1010→Distillation is not a separate pipeline. It is **pruning the cell graph**. Remove cells not needed for the target task. The engine evaluates the pruned sheet. If conservation holds, deploy.
  1011→  1011→
  1012→  1012→This is the eighth simplification: **you delete the distillation pipeline and the edge runtime.** They become cell graph pruning and substrate selection.
